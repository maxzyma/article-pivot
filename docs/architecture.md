# Architecture

## Boundaries

Article Pivot separates five implementation boundaries:

1. The content core owns versioned canonical documents, translation overlays,
   deterministic rendering, and validation.
2. Source and discovery adapters own source-specific fetching and parsing.
3. Archive adapters own local or Git-backed content layouts and public indexes.
4. Publisher adapters own remote target rendering, idempotent writes, read-back,
   reconciliation, and rollback.
5. Private orchestration owns schedules, credentials, routing, runtime state,
   notifications, approvals, and dead letters.

Agent skills invoke these capabilities but do not reimplement them.

## Data flow

```text
RawSnapshot
  -> CanonicalDocument
  -> TranslationOverlay (optional)
  -> CanonicalPackage
     -> ArchiveArtifact -> ArchiveReceipt
     -> PublicationArtifact -> PublishReceipt
```

Markdown, HTML, and target JSON are derived artifacts. They are never the
cross-target source of truth.

## Repository roles

- `article-pivot`: reusable processing and adapter contracts.
- agent skill layer: thin agent interaction guidance.
- private automation workspace: scheduler and control plane.
- `trending-diggest`: public archive and reading site.

`trending-diggest` and DingTalk are sibling outputs of one canonical package.
Neither output is generated by reading the other back as source.

## Migration rule

Existing producers remain authoritative until a replacement has passed golden
fixture tests, target dry-runs, artifact diffs, canary writes, and read-back
verification. Migration uses parallel execution with only one active writer.
